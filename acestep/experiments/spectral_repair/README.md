## Запуск из корня ACE-Step

Используйте уже установленное окружение проекта; новые зависимости не нужны.

```bash
.venv/bin/python -m acestep.experiments.spectral_repair --help
.venv/bin/python -m acestep.experiments.spectral_repair benchmark /tmp/spectral-dsp --duration 4
.venv/bin/python -m acestep.experiments.spectral_repair benchmark /tmp/spectral-ace --ace --duration 8 --device cuda:1
```

Выходной каталог benchmark должен быть новым или пустым. Без `--ace` нейросетевая
ветвь отмечается `not_run`. Эталонный кандидат существует только как явно названный
`oracle_control_NOT_ACE`; он не считается результатом модели.

Пример `regions.json`:

```json
[
  {"start": 1.5, "end": 3.0, "low": 800, "high": 1200,
   "feather_time": 0.025, "feather_hz": 50},
  {"start": 4.0, "end": 4.3, "low": 2000, "high": 6000}
]
```

```bash
.venv/bin/python -m acestep.experiments.spectral_repair repair input.wav repaired.wav --ace --regions regions.json --device cuda:1
.venv/bin/python -m acestep.experiments.spectral_repair repair input.wav repaired.wav --candidate candidate.wav --mask mask.npy --mode original-phase
```

Результаты: WAV FLOAT (без скрытого ограничения пиков), JSON с параметрами,
выравниванием и ресурсами, PNG до/после отдельно для каждого канала.
Если пик превышает 1, это видно в JSON; для воспроизведения следует учитывать
запас по уровню. Нормализация не применяется, чтобы не менять оригинал целиком.

`mask.npy` — конечные числа [time, frequency] в [0,1]. Число временных кадров
определяется `analyze(original, config).shape[1:]`. Произвольные маски загружаются
без pickle. Прямоугольники объединяются максимумом; feather действует внутрь
границ. Одна маска применяется к обоим каналам, каналы не сводятся в моно.

Настройки `--fft-size`, `--hop-length`, `--window` задают STFT. `--sample-rate`
проверяет частоту входа, не выполняет ресемплинг. DSP работает с моно/стерео;
провайдер ACE требует явно подготовленного стерео 48 кГц, соответствующего VAE.
Предварительно сгенерированный кандидат обязан иметь ту же длину и частоту.

## Параметры модели

`--ace-params params.json` для repair передаёт объект аргументов существующего
`generate_music`; источник, длину, batch и временные интервалы задаёт провайдер.
Пример режима с малым шумом:

```json
{"task_type": "cover-nofsq", "cover_noise_strength": 0.9,
 "inference_steps": 8, "seed": 101, "captions": "Instrumental music",
 "lyrics": "[Instrumental]"}
```

Для вокала передавайте соответствующие caption/lyrics. Восстановление вокала
на этом цикле не подтверждено. `repaint_strength` управляет инъекцией контекста,
а не величиной начального шума. `cover_noise_strength` имеет обратную шкалу:
больше значение — меньше шума. Реальный старт округляется к сетке timesteps;
с восемью шагами близкие значения могут дать один режим.

Для benchmark `--ace-params` принимает список объектов `name`, `parameters`.
По умолчанию проверяются repaint, cover-nofsq с шумом 0.9 и вариант 0.75 с retake.
Каждый кандидат используется в complex и original-phase смешивании. Фиксируются
seed VAE и диффузии; CUDA не обещает побитовую повторяемость на другом оборудовании.

Провайдер использует текущий механизм инициализации и CPU offload, уважает
`ACESTEP_GENERATION_DEVICE`, не меняет `ACESTEP_LM_DEVICE` и не загружает LM.
Загрузка весов локальная (`HF_HUB_OFFLINE=1`, если переменная не задана ранее).
Никаких LoRA не обучается, модели изображений не используются.

## Протокол и ограничения

Пять случаев: паразитный тон, полосовой шумовой импульс, потеря полосы, несколько
дефектов, чистая запись с ненулевой тестовой маской. Для каждого сохранены WAV,
маска и параметры повреждений. Фикстура — синтетическая музыкальная последовательность
со стерео, гармониками и атаками; вокал и реальные плотные записи требуют отдельной
проверки. Чистый тест с ненулевой маской измеряет ненужные изменения, а нулевая
маска проверяется отдельно на точное сохранение отсчётов.

Контроли: без обработки, комплексная интерполяция по частоте, notch для тона /
интерполяция по времени для остальных дефектов. Простая интерполяция фазы может
сама создавать ошибки, поэтому сравниваются WAV- и спектральные метрики.

Изменённая STFT обычно не является согласованной: после iSTFT/STFT ненулевые
изменения возможны вне выделенных бинов. Мы измеряем `outside_change_rms` и
`consistency_rms`. Нулевая маска сохраняет отсчёты точно; при ненулевой маске
изменения во времени ограничены поддержкой окон, не только центрами кадров.

Оценка сдвига — целочисленная, максимум 50 мс, общая для стерео. Корреляция ниже
0.2 или максимум на границе поиска не применяют сдвиг; показатель сохранён.
Это не подтверждает фазовую совместимость, сохранение темпа или вокального исполнения.
Локальное растяжение и дробные задержки не реализованы.

`results.json` содержит RMSE, selected spectral RMSE, LSD с порогом -140 dB,
энергию внутри маски, изменение вне маски, ошибку огибающей/стереокорреляции.
RSS — high-water всего процесса Linux, не прирост метода. CUDA peak — аллокатор
PyTorch, отдельно от ежесекундных nvidia-smi замеров общей памяти/загрузки GPU.
Индексы CUDA и nvidia-smi могут отличаться: в испытанной системе CUDA 0 =
RTX 5060 Ti, CUDA 1 = RTX 3060, а nvidia-smi нумерует их в обратном порядке.
Сопоставляйте название/UUID карты, а не только индекс. Короткие пики между
замерами могут отсутствовать. Загрузка модели измеряется отдельно.

В `blind/` находятся случайно упорядоченные WAV без подсказок; ключ — рядом,
`blind_key.json`. Прослушивание человеком в наушниках не проведено. Не считайте
метрики или спектрограммы доказательством превосходства звучания.

## Тесты

```bash
.venv/bin/python -m unittest acestep.experiments.spectral_repair.core_test acestep.experiments.spectral_repair.ace_test
```

Условия лицензии исходного проекта, весов и зависимостей сохраняются; веса в модуль
не включены. Проект указывает MIT в LICENSE и checkpoints/README.md; это не заменяет
условия конкретных заменённых/дополнительно загруженных весов и исходных записей.

## Локальная лаборатория Gradio

```bash
.venv/bin/python -m acestep.experiments.spectral_repair.lab --output /tmp/spectral-lab --source input.wav --port 7861
```

Панель: http://127.0.0.1:7861. Изменяются шаги, CFG, Shift, seed, модель, repaint,
параметры cover/retake, описание и текст; поддерживается импорт JSON из Gradio.
Base использует заданный CFG, Turbo в текущем генераторе принудительно ставит 1.

Benchmark на реальном музыкальном фрагменте:

```bash
.venv/bin/python -m acestep.experiments.spectral_repair benchmark /tmp/spectral-real --ace --source input.wav --offset 120 --duration 16 --device cuda:0
```

Исходная запись — относительный эталон только для добавленных искусственных
повреждений, а не гарантированно чистый оригинал. Для вокала передайте параметры
с подходящими captions/lyrics/vocal_language через --ace-params. Прямое сравнение
на неповреждённой области можно выполнить в лаборатории без добавления дефекта.

Ранние отчёты оценивают только проверенные конфигурации. В лаборатории адаптер
явно выбирает task-specific instruction; ранние benchmark-прогоны использовали
общую инструкцию generate_music. Сохранённый JSON показывает фактический CFG.
